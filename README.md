# DanmakuForge 弹幕锻坊

**`.brg` 弹幕工程的可视化编辑器。**

弹幕是一帧一帧算出来的，改一个角度、一条条数、一次发射时机，屏幕上就是完全不同的东西。
DanmakuForge 让你在**看得见子弹**的画布上直接改：拖手柄调角度，拉时间轴改节奏，
属性面板里 91 个字段一个不少，改完存回原文件——原文件里那些本工具不认识的字段，
一个字节都不会丢。

双击 `build\DanmakuForge.exe` 就能用。它读写的是 SlimeStorm 的 `.brg` 格式——
只要你的工程认得这种格式，它就能派上用场。

---

## 为什么值得用它

**无损是硬承诺。** `.brg` 是 C# XmlSerializer 风格的 XML，一张卡动辄一百多个字段，
而引擎侧的语义解析器只认得其中一半。如果拿解析后的数据当模型再存回去，
不认识的字段会被**静默抹掉**——等你发现时，美术、特效、绑定都没了。
所以这里做的是**保真层**：保留完整 XML 树与权威元素顺序，只对你动过的那几行动刀。
「打开 → 保存」这条路上，文件的其余部分逐字节不变。

**预览是真的在跑弹幕，不是示意动画。** 画布里的子弹由一套真实的弹幕运行时驱动：
弹池 + 批量渲染 + 自机狙瞄准 + 逐帧弹道事件，和实际 play 出来的是同一套代码路径。
而且每次改动都会**固定种子从头重放到当前帧**——同一个文件跑两遍，输出逐字节相同。
所以「这个参数改了之后难度变了多少」是能复现、能对比的，不靠手感猜。

**改弹幕的动作都被压到最短。** 角度是一个可以拖的方向箭头，范围是一片可以撑开或收拢的扇形，
发射半径是一个可以拽远的圆，条数、周期、层差都在画布上直接调；
时间轴上一段弹幕就是一根可拖的条，左端是起始帧，右端红线是持续帧；
弹幕之间的先后关系摊在轨道上，一眼能看出重叠与空档。

**每一处改动都有回归测试兜底。** 格式往返、写盘端到端、界面逻辑、弹道指纹，
一条命令跑完（`--selftest`）。这不是给用户看的门面，而是改缓存、改渲染、改坐标换算时
真正拦住回归的东西。

```
│ 时间轴 适配 事件… · 删除单弹 撤销压制 清空压制 存压制 · 宿主 X/Y · 叠层开关 │
├─────────────┬────────────────────────────────────────┬──────────────────────┤
│ 结构树      │ 画布（780×960 设计空间）               │ 属性（91 个字段）    │
│ 发射器列表  │ 网格 · gizmo 手柄 · 标签 · 自机小球 · 框选│ 按 10 个分组折叠     │

├─────────────┴────────────────────────────────────────┴──────────────────────┤
│ 时间轴：一发射器一轨 —— 拖左端改起始帧、拖右端红线改持续帧、标尺拖动预览   │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 能做什么 |
|---|---|
| 结构树 | 所有发射器一览（`序号 标签 Way·周期`，停用的标 `[停用]`），点击定位、`Ctrl` 多选批量改 |
| 画布 | 拖手柄改**发射角度 / 范围 / 发射半径 / Way 条数**；拖发射器本体改位置（相对宿主或绝对坐标）；拖自机小球改瞄准基准；框选、网格吸附、标签避让 |
| 时间轴 | 拖片段改 `StartTime`，拖右边缘改 `Duration`，标尺 scrub 直接看那一帧，`Ctrl` 滚轮缩放 |
| 属性面板 | 全部 **91 个非容器字段**：基本 / 发射器运动 / 发射几何 / 随机 / 粒子 / 粒子随机 / 行为 / 闪烁 / 背图 / 绑定 |
| 事件编辑器 | 事件组与事件的条件、结果字段（含 `changename` 与 `ChangeName*` 的同步） |
| 删除单弹 | 在画布上点掉某一颗具体子弹（见下） |

## 快速开始

**发布版**

```powershell
.\build\DanmakuForge.exe                                   # 空界面，Ctrl+O 打开文件
.\build\DanmakuForge.exe --open "D:\cards\my_card.brg"     # 打开即编辑
.\build\DanmakuForge.exe --open "my_card.brg" --play       # 打开即播放，方便先看现状
```

**从源码**（需要 Godot 4.7.x，本工程在 4.7.2 上开发）

```powershell
godot --path .                                    # 主场景就是编辑器
godot --path . -- --open "my_card.brg" --events   # 顺带弹出事件编辑器
```

窗口的排版尺寸固定为 `1580×1240`，按屏幕可用区域整体等比缩放——输入坐标由引擎换算，
所以小屏上不会出现"鼠标点不准"。启动时会打印一行 `逻辑 1580x1240 → 物理 WxH（缩放 N.NN×）`，
分辨率不匹配是看得见的，而不是让人以为字变小了。

## 快捷键

| 键 | 作用 |
|---|---|
| `Ctrl+O` / `Ctrl+S` | 打开 / 保存（没有路径时自动转为另存为） |
| `Ctrl+Z` / `Ctrl+Y`（或 `Ctrl+Shift+Z`） | 撤销 / 重做 |
| `Ctrl+A` | 全选发射器 |
| `Ctrl+C` / `Ctrl+V` | 复制 / 粘贴选中发射器（新 ID，标签加 `_copy`） |
| `Del` / `Backspace` | 删除选中的发射器 |
| `空格` | 播放 / 暂停 |
| `Ctrl+T` | 显示 / 隐藏时间轴 |
| `F` | 时间轴适配整段 |
| `方向键` / `WASD` | 移动自机小球（播放时用它看自机狙打到哪里） |
| `Esc` | 退出「删除单弹」拾取模式 |

## 命令行

除启动参数外，所有自检都支持 `--headless`，适合挂到 CI 或脚本里。

| 参数 | 说明 |
|---|---|
| `--open <path>` | 启动即打开该 `.brg`（旧别名 `--brg-editor`） |
| `--play` / `--events` | 打开后自动播放 / 自动弹出事件编辑器 |
| `--selftest` | **一次跑完全部自检**：格式往返 → 写盘端到端 → 界面逻辑 → 弹道指纹 |
| `--roundtrip <目录[,目录]>` | 对目录下所有 `.brg` 做「解析 → 序列化 → 逐字节比对」并附带改动隔离检查 |
| `--editor-test <file>` | 写盘端到端：删/增发射器、改字段之后，结果仍能被语义层载入且幂等无损 |
| `--ui-test <file>` | 无头驱动界面逻辑：选中、拖拽手柄、时间轴、撤销重做、事件、压制 |
| `--bullet-fp <N> <目录>` | 弹道确定性指纹：每条 `.brg` 跑 N 帧，输出可逐字节比对的校验值 |
| `--brg-dump <N>` / `--brg-sim <N>` | 打印前 N 帧的发射几何 / 逐帧弹道 |
| `--brg-file <path>` | 指定上述自检的输入样本（默认用 `samples/` 里的参考工程） |
| `--shot <png> --shot-delay <t[,t2]> --quit-after <t>` | 截图（**必须窗口化**；无头模式读不回画面） |

历史参数名仍可用：`--brg-editor`、`--brg-editor-play`、`--brg-editor-events`、
`--brg-roundtrip`、`--brg-editor-test`、`--brg-ui-test`。
注意 `--headless` 下本工程的退出码恒为 1（引擎在退出时报告对象泄漏），
**判断结果请看输出里的 ✅ / ❌**。

## 怎么改一张卡

1. `DanmakuForge.exe --open "D:\cards\my_card.brg"`，先按 `空格` 播放一遍看看现状。
2. 在画布或时间轴上改。改属性时画布上的 gizmo 会跟着数值动，属性面板的数也会跟着拖拽变，
   两边不会打架。
3. `Ctrl+S` 存回原路径。`.brg` 是纯数据文件，你的工程下次载入它时就是新的表现，
   不需要重新编译。

**给工程新增一张卡**：用「另存为」放到工程约定的目录即可。至于「工程怎么知道有这张新卡」，
取决于你自己的工程——如果是靠一份索引/清单文件登记符卡，那么在那边加一条记录就行。
本工具只负责 `.brg` 文件本身，不会去动你工程里的任何配置文件。

### 只删掉某一发弹：单弹压制

`.brg` 里**没有「单颗子弹」这个实体**——子弹是运行时按 `Way` / `Circle` / `Count`
逐帧算出来的，XML 里找不到它，也没法表达「第 1234 号子弹」这种说法。
所以「删掉那一发」既要能选中，又不能改坏原文件，做法是旁挂补丁：

1. 点工具栏「删除单弹」，在画布上点中那颗弹（画布会提示拾取到的身份）。
2. 连点几发，攒够了按「存压制」。
3. 补丁写到 **`my_card.brg.patch.json`**，而 `.brg` 本体一个字节都不动。

身份用 `发射器序号:出生帧:该帧内第几发` 表示，即使前面有弹被压制，
序号也照常自增——否则压掉一发会让后面所有弹的编号前移，补丁就错位了。
读取这份补丁的是运行时（`BrgPlayback` 会自动加载同目录的 sidecar），
所以压制是**真实的玩法改动**，不只是预览效果。

## 目录结构

```
scenes/DanmakuForge.tscn        编辑器主场景（启动入口）
scripts/editor/                 编辑器本体
  BrgEditor.gd                    主界面：工具栏、结构树、属性面板、撤销、播放控制、窗口缩放
  BrgCanvas.gd                    画布：网格、gizmo、四类拖拽手柄、命中测试、框选、标签避让
  BrgDocument.gd                  保真层：无损 XML 树、权威顺序表、字段与事件读写
  BrgTimeline.gd                  时间轴轨道编辑器
  BrgEventEditor.gd               事件组 / 事件编辑器
scripts/core/                   弹幕运行时（弹池、批量渲染、播放器、贴图烘焙、坐标换算）
scripts/tools/EditorCli.gd      命令行入口与自检（autoload `Cli`）
tools/bake_bullets.gd           预烘焙弹幕贴图到 assets/textures_baked/
tools/sync_core.ps1             同步运行时快照（见 VENDOR.md）
assets/                         弹幕贴图与预烘焙档
samples/                        自检用的参考工程
docs/EDITOR.md                  实现细节：保真规格、踩坑记录、数量化结论
docs/BRG_FORMAT.md              `.brg` 格式说明
VENDOR.md                       运行时的来源与漂移校验
```

编辑器预览用的运行时（`scripts/core/`）与它服务的工程是**同一套实现**的只读快照，
方向永远是「工程为准，这里同步」，靠 `tools/sync_core.ps1` 拉起，
并用弹道指纹在两个工程之间逐行比对来确认没有漂移。细节见 [`VENDOR.md`](VENDOR.md)。

## 自检与构建

```powershell
godot --headless --path . --import            # 导入校验（无输出 = 零错误）
godot --headless --path . -- --selftest       # 全部自检

# 导出（先关掉正在运行的实例，否则 exe 被占用）
Get-Process DanmakuForge,Godot* -ErrorAction SilentlyContinue | Stop-Process -Force
godot --headless --path . --export-release "Windows Desktop" "build\DanmakuForge.exe"
```

改动解析、渲染或坐标换算之后，建议额外跑一次跨工程比对：
同一批 `.brg` 在两边的 `--bullet-fp` 输出必须逐行一致。这是保证「编辑器里看到的弹道
与工程里实际跑的弹道是同一个东西」的硬闸门。

## 已知边界

- **历史备份不保证往返。** 早期版本或手工改过的 `.brg` 如果换行与编码跟当前产物不同，
  格式往返测试会如实报出差异。当前由本工具产出的文件全部通过。
- **只有被解析的字段会体现在预览里。** 属性面板能编辑全部 91 个字段，但预览（和多数引擎侧实现）
  只响应其中一部分：发射器自身运动、`Reflect*`、`Twinkle*`、`BackImage*` 这类字段能改、能存，
  暂时看不到效果。缺的那部分要靠逐步补语义。
- **不做坏事。** 只碰 `.brg` 与它自己的压制 sidecar，不动工程里的任何配置或索引文件；
  完全离线，除了引擎自己的 `user://` 缓存目录（弹幕贴图的烘焙缓存）不在别处留东西。
- 界面排版尺寸固定，屏幕比例不匹配时左右会有黑边，这是为了版面可预测而做的取舍。
